# Issues 16–19: administrator volunteer data editing

Application commit `b5f1408` (local `main`). Issues 16–19 add an administrator-only Volunteers tab: edit names and emails (#16), add volunteers (#17), remove volunteers by marking them inactive (#18), and an append-only change history with the administrator who made each change (#19).

## Implementation and review

Each ticket was built test-first in its own worktree and merged onto an integration branch (`issue-16-volunteers-tab`, then `volunteers-tab-17-19`). Two-axis reviews (standards and spec) ran after each integration.

- #16 review: shared roster ordering and email-shape rule. User decisions: an email edit is rejected when a saved roster link would route that email to another volunteer; the linked sign-in account's email is updated with the volunteer's; duplicate names stay allowed.
- #17–#19 review: the first history design read the whole `volunteer_changes` table on every operation and silently capped it at 50, contrary to `docs/performance/bounded-work-audit.md`. With user approval, history was moved out of the snapshot diff: entries are appended by explicit INSERT in the same commit batch, and the tab pages history newest first (50 per page, keyset on `occurred_at, id`) with Show older. No-op edits are rejected with "No changes to save." Change kinds and fields have one owner.
