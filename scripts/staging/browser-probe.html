Staging Worker browser probe

This page sends the three feasibility reads to the staging Worker from an allowlisted origin and records transport facts, per-operation wall time, and what each attempt cost in Sheets reads (the Worker's read count plus its per-read timings, when the deployment exposes them). It is a measurement tool: it needs the staging deployment to exist, and it displays aggregates, one record per attempt, and no response bodies.

Query parameters: api (the staging Worker /exec URL), client (the staging OAuth client id), label (the report name, default probe), attempts (attempts per operation, default 5, at most 60), readPlan (legacy by default, or portable to reserve 2 identity / 4 domain reads), and hostDeployedAt (the expected X-Staging-Host-Deployed-At timestamp; required for portable). The probe waits until that deployment is at least 95 seconds old, then retains and excludes responses from another host version from warm distributions. The pool has at most 4 requests; reports count the observations that actually overlapped at least 3 requests. Every target request first reserves its selected read cost in the probe host's shared ledger.

Never run this against production. The probe refuses any target that is not a *.workers.dev host whose name contains staging; confirm the staging deployment was approved before starting.
